POLIEDRAW · 1.0.002

1. Visão geral e propósito

O Poliedraw aproxima criatividade, tecnologia e aprendizagem em uma ferramenta escolar simples. A interface permite descrever uma ideia, visualizar a imagem gerada, baixá-la e manter uma galeria vinculada ao perfil.

Requisitos

IDEntrega
RF01–RF02Login independente para professor e aluno.
RF03–RF05Redirecionamento por perfil, envio de prompt e exibição Gemini.
RF06–RF07Persistência e consulta das imagens.
RF08–RF09Administração de alunos e exclusão de imagens.

Tecnologias

CamadaImplementação
IA@google/genai com gemini-2.5-flash-image.
BancoMySQL com mysql2/promise.
SQLiteDependências instaladas; adaptador ainda não conectado.
UIHTML5, CSS3 e JS em HTML/, CSS/ e JS/.

Requisitos não funcionais

  • ES Modules e Express 5.
  • JSON de até 50 MB para imagens Base64.
  • Infraestrutura configurada por .env.
  • CORS habilitado para integração local.

             ▼

  autenticação · CRUD · tabelas · /api/gemini
       ├── mysql2/promise → MySQL
       └── @google/genai → Gemini 2.5 Flash Image

Fluxo de geração

  1. Login em /professores ou /alunosLogin.
  2. Frontend grava usuarioId, usuarioTipo e usuarioNome no localStorage.
  3. frontGemini.js envia prompt para /api/gemini.
  4. Backend aplica prompt de sistema e chama o Gemini.
  5. Texto e inlineData voltam como texto e imagens.
  6. Imagem é exibida, baixada e enviada a /salvarImagem.
  7. Galeria usa /minhasImagens e /imagens/:id.

3. API · autenticação e imagens

Base local: http://localhost:3000. Entradas e respostas são JSON; imagens trafegam como Data URL/Base64.

POST /professores

Autentica professor. Sucesso: { success, id, nome }; credencial inválida: 200 { success:false }; banco: 500.

POST /alunosLogin

Mesmo contrato, consultando a tabela de alunos.

POST /salvarImagem

{ "id_usuario": 1, "tipo_usuario": "aluno", "prompt": "Mapa do ciclo da água", "imagem": "data:image/png;base64,..." }

id_usuario e imagem são obrigatórios; ausência retorna 400. Sucesso retorna confirmação.

GET /minhasImagens?id=&tipo=

Exige os dois parâmetros, filtra por usuário/perfil e ordena por data_criacao DESC.

DELETE /imagens/:id

Exclui por id_imagem; registro ausente retorna 404.

Manutenção: a rota DELETE /imagens/:id está declarada duas vezes com implementação equivalente.

3. API · administração e Gemini

GET /alunos

Retorna todos os registros de alunos.

POST /cadastrarAlunos

{ "nome": "Ana", "email": "ana@sistemapoliedro", "senha": "segredo" }

Retorna { success, id }; erros de inserção são 500 no código atual.

PUT /alunos/:id

Atualiza nome e e-mail. O e-mail precisa terminar em @sistemapoliedro; e-mail inválido: 400; ID ausente: 404.

DELETE /alunos/:id

Exclui por ID. Histórico referenciado: 400; ID inexistente: 404.

POST /api/gemini

{ "prompt": "Uma célula vegetal com suas estruturas identificadas" }

Sem prompt: 400. Sucesso: { texto, imagens: ["data:image/png;base64,..."] }. Falha do Gemini: 500.

Regras didáticas

  • Fidelidade, composição limpa e clareza visual.
  • Neutralidade de estilo quando não solicitada.
  • Interpretação educacional para pedidos vagos.
  • Sem violência, sexualidade, conteúdo ofensivo, marcas reais, celebridades ou textos longos não pedidos.

BD/banco.sql é a referência declarativa; o backend também garante as tabelas no boot.

5. Configuração e execução

Instalação

git clone https://github.com/MarcosGitCode/Poliedraw.git
cd Poliedraw
npm install

Arquivo .env

GEMINI_API_KEY=SUA_CHAVE_DE_API_DO_GEMINI
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASS=sua_senha
DB_NAME=poliedro_ai
PORT=3000

Não versione este arquivo nem publique segredos.

Banco

mysql -u root -p < BD/banco.sql

O script cria poliedro_ai, as quatro tabelas e dados de exemplo. O backend repete a garantia via CREATE TABLE IF NOT EXISTS.
